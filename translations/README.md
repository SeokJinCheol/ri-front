# 한국어·영어 번역 관리

`translations.xlsx`가 번역의 원본입니다. `Translations` 시트에서 문구를 관리합니다.

| 열 | 용도 |
| --- | --- |
| `key` | 코드의 `t('key')`와 연결되는 고유 키. 기존 키는 유지합니다. |
| `ko` | 한국어 문구 |
| `en` | 영어 문구 |
| `source` | 최초 사용 위치 참고. 공통 문구는 여러 화면에서 재사용합니다. |

`{{v0}}`, `{{v1}}`, `{{name}}` 같은 치환 변수는 이름을 유지하고, 언어에 맞게 위치를 바꿀 수 있습니다. 두 언어의 변수 목록은 같아야 합니다. 문구는 수식 대신 텍스트로 입력하세요. 시트 이름과 첫 행의 `key`, `ko`, `en`은 변경하지 않습니다.

## 적용

1. 엑셀의 `ko` / `en` 열을 수정하고 저장합니다.
2. 실행 중인 Vite 개발 서버는 파일 변경을 감지하여 화면을 새로고침합니다. 새로고침 전 입력 중인 내용은 저장하세요.
3. 배포는 기존 빌드 명령(`npm run build:nginx`, `npm run build:electron`)을 다시 실행합니다.

Vite가 엑셀을 읽어 `virtual:translations` 모듈을 생성합니다. 브라우저와 Electron에는 번역 데이터만 포함되며 엑셀 파서나 별도 파일 요청이 필요하지 않습니다. 빌드된 앱의 문구를 바꾸려면 다시 빌드·배포해야 합니다.

새 문구는 고유 키와 두 언어를 한 행에 추가한 뒤 컴포넌트에서 `useLocale().t`로 사용합니다. 일반 함수·스토어는 `@/i18n`의 `t`를 사용합니다. 누락 번역, 중복 키, 치환 변수 불일치, 코드에서 참조하는 미등록 키는 개발/빌드 오류로 표시됩니다.

기본 언어는 한국어이고 `app-locale`에 선택을 저장합니다. 언어 변경은 현재 폼과 대화 상태를 유지하며 날짜 표시와 문서의 `lang`도 변경합니다. 사용자 입력, 문서 본문, AI 답변, 서버에서 받은 메시지는 원문 그대로 표시합니다. 이미 표시 중인 알림은 발생 당시 언어로 유지되며 이후 알림부터 선택한 언어를 사용합니다.

검증: `npm run test:i18n` (Node.js 22.18 이상), `npx tsc --noEmit`.
